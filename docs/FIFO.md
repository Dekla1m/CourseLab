# FIFO с чтением valid/ready

Универсальная очередь для RX, TX и результатов шифратора. [FIFO.v](../CourseLab.srcs/sources_1/FIFO.v)

## Контракт

- WORD_SIZE >= 1; FIFO_DEPTH — степень двойки не меньше 2. Доступно ровно FIFO_DEPTH слов.
- Два clock: clk_in_write и clk_in_read. Можно подключить один общий clock.
- Запись: на фронте clk_in_write при write_enable && !full.
- Чтение: на фронте clk_in_read при read_valid && read_ready. Получатель захватывает data_out, видимый перед этим фронтом.
- При read_valid=1 и read_ready=0 данные и read_valid сохраняются до принятия или reset.
- Первое слово подготавливается автоматически, без запроса от потребителя. Поэтому отдельный адаптер к Key_input_order не требуется.
- empty = !read_valid: в домене чтения сейчас нет подготовленного слова. После удалённой записи возможна консервативная задержка синхронизации/предвыборки.
- full относится только к домену записи; read_valid/empty/data_out — только к домену чтения. Управления и данные должны быть синхронны соответствующему clock.
- full=1 также во время общего reset и локального восстановления записи. Источник не получает ложного разрешения на запись до снятия локального сброса.
- Запись приостанавливает `write_enable`, потребление — `read_ready`. Остановка чтения оставляет запись доступной до заполнения FIFO.


## Почему ёмкость не увеличилась на слово

Указатель чтения продвигается только после handshake потребителя. Выходной регистр хранит копию текущей головы, а её место в памяти до приёма остаётся занятым. Предвыборка при ready=0 не освобождает место на стороне записи. Поэтому FIFO глубиной 64 принимает ровно 64 слова, включая подготовленную голову.

После принятия слова синхронно читается следующий адрес, если синхронизированный указатель записи показывает наличие данных. При накопленной очереди возможна выдача одного слова каждый такт чтения без пузырей. На границе пустой очереди допускается задержка CDC/предвыборки.

## Указатели и reset

Используются локальные двоичные указатели с битом оборота, зарегистрированный Gray-код и две ступени ASYNC_REG для каждого перехода. Через CDC не передаётся двоичный адрес. full сравнивает следующий указатель записи с синхронизированным указателем чтения с инверсией двух старших Gray-битов.

Общий reset асинхронно устанавливает локальные сбросы; снятие синхронизируется независимо каждым clock. Память не очищается: сброс указателей отменяет её содержимое. read_valid и data_out очищаются, empty=1, full=1 до восстановления домена записи. При остановленных clocks сброс действует, а восстановление ждёт их запуска. Частичный независимый сброс только одной стороны не поддерживается.

При подключении разных clocks проверяются CDC и физические ограничения переходов Gray. Эта проверка входит в финальный аппаратный этап.

## Унификация

- RX UART: WORD_SIZE=10 — байт и два флага ошибки.
- TX UART: WORD_SIZE=8.
- Результат шифратора: WORD_SIZE=129, data_in={data_output_last, data_output}. На чтении data_out[128] — last, data_out[127:0] — блок. FIFO не интерпретирует содержимое слова.

Для выхода шифратора write_enable подключается к data_output_valid. Так как вычислитель не ждёт ready, диспетчер обязан заранее обеспечить место для результата; проверка full только в момент результата не заменяет резервирования. Запись при full отклоняется.

Физическая ширина и глубина задаются при сборке. Рабочий лимит ёмкости через регистр относится к будущей системной конфигурации. [Программируемые настройки](SYSTEM_BUS_AND_PROGRAMMER.md#настройки-во-время-работы)

## Модульные проверки

- `tb_fifo.v` проверяет один FIFO и эталонную очередь. Отдельные конфигурации: 8×64, 10×16, 1×2 и 129×4. Последняя использует общий clock. Проверяются reset, полная ёмкость, паузы чтения, непрерывная выдача, переходы через границу указателя и остановка clocks.
- `tb_key_input_order.v` напрямую подаёт байты в формирователь ключа. Проверки удержания результата, границ длины, ошибок UART и сброса прошли: 17 сценариев и 18 результатов разбора.

Запуск из корня проекта — [check_fifo_and_key.ps1](../work/check_fifo_and_key.ps1), параметры `-Test fifo` и `-Test key`. Журналы хранятся в [outputs/unit_tests](../outputs/unit_tests). Оба TB подключены к `sim_1` и запускаются отдельно.
