# Encrypt_TOP — интерфейс и расписание

[Encrypt_TOP.v](../CourseLab.srcs/sources_1/Encrypt_TOP.v) шифрует 128-битный блок за **37 тактов от приёма**. Девять четырёхстадийных LSX и финальный XOR образуют конвейер, который принимает один блок за такт внутри сообщения. [Общий RTL конвейера](../CourseLab.srcs/sources_1/kuz_round_pipeline.v) Раундовые ключи поступают из общего активного банка в [kuz_TOP](../CourseLab.srcs/sources_1/new/kuz_TOP.v).

## Интерфейс блока и сообщения

- Входные данные и `data_input_last` принимаются по `data_input_valid && data_input_ready`. В [kuz_TOP](../CourseLab.srcs/sources_1/new/kuz_TOP.v) вход данных открывается после готовности ключей. После приёма блока с `last=1` вход закрывается до выдачи этого блока.
- `data_output_valid=1` отмечает один результат на каждом таком такте. При соседних результатах `valid` остаётся высоким. Данные и `data_output_last` хранятся до следующего результата или сброса. Диспетчер заранее резервирует место в FIFO для каждого принятого блока.
- `busy_all_message` поднимается при приёме первого блока и остаётся высоким в паузах между блоками. Он снимается при выдаче результата с `data_output_last=1` или при синхронном сбросе. Внутри сообщения следующий блок может входить на том же фронте, на котором выходит предыдущий.

## Общий банк ключей

- Исходный ключ `start_key_input[255:0]` принимается в домене 200 МГц по `key_input_valid && key_input_ready`. Обвязка разрешает приём, если `kuz_TOP` свободен между сообщениями. При одновременном приёме первого блока и запросе ключа приоритет у блока.
- [kuz_key_loader](../CourseLab.srcs/sources_1/kuz_key_loader.v) фиксирует исходный ключ и передаёт запрос на 100 МГц. [kuz_key_schedule](../CourseLab.srcs/sources_1/kuz_key_schedule.v) рассчитывает новый набор за 33 своих такта. Повторная передача того же исходного ключа использует ранее рассчитанный набор.
- Формирователь держит готовый набор до подтверждения. На 200 МГц `kuz_TOP` записывает все 1280 бит на одном фронте с `round_keys_input_valid && round_keys_input_ready`. Пока запрос в работе, приём данных закрыт. После сброса вход закрыт до первой записи банка.
- K1 занимает старшие 128 бит, K10 — младшие. ENC и DEC читают один активный набор в разном порядке. Банк сохраняется на всём протяжении сообщения.

## Тактовое расписание

1. **t0** — данные и метка конца входят во входной регистр.
2. **t1–t36** — девять раундов на K1…K9. В каждом раунде по одному такту на XOR, S, R⁸ и R⁸.
3. **t37** — финальный XOR с K10 и выдача результата с `last` и `valid`. Блоки, принятые на соседних фронтах, выходят на соседних фронтах. После результата с `last=1` приём нового сообщения возможен на следующем фронте, если `kuz_TOP` готов.

## Проверка

- **Encrypt_TOP, 5/5 сценариев.** 46 результатов с задержкой 37 тактов. Проверены эталонный шифротекст, непрерывная подача, пустой слот, ожидание конца сообщения и сброс с несколькими блоками в тракте. [Журнал](../outputs/unit_tests/encrypt_top/simulation.log)
- **kuz_key_schedule, 3/3 сценария.** Проверены десять ключей RFC 7801, порядок параллельной шины, готовность на t33, повторная загрузка и сброс во время подготовки. [Журнал](../outputs/unit_tests/key_schedule/simulation.log)
- **kuz_key_loader, 3/3 сценария.** Проверены два тактовых домена, удержание результата до подтверждения, повтор ключа и сброс при обновлении. [Журнал](../outputs/unit_tests/key_loader/simulation.log)
- **kuz_TOP, 5/5 сценариев.** Тринадцать результатов. Проверены двухблочные сообщения без паузы в ENC и DEC, повторное использование ключей, отложенные смены режима и ключа и работа с новым набором. [Журнал](../outputs/unit_tests/kuz_top/simulation.log)
