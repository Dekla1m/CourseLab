# Правила работы с CourseLab

Правила пользователя от 02.11.2026 действуют для всего текущего проекта.

1. Только чистый Verilog (`.v`), включая testbench. Не создавать `.sv`, не использовать режим компиляции SystemVerilog и его языковые конструкции.
2. Запрос «верифицировать/протестировать модуль» означает только симуляцию. Не запускать синтез, имплементацию или timing-анализ без отдельного явного поручения.
3. Один testbench — один проверяемый модуль, с одним экземпляром DUT. Дочерние зависимости самого DUT допустимы; подключать другие проверяемые блоки для интеграции нельзя без отдельного поручения пользователя.
4. При необходимости проверить параметры модуля запускать тот же TB с разными параметрами, а не создавать несколько вспомогательных модулей/экземпляров.
5. TB писать в стиле пользователя: отдельные объявления, читаемые отступы и пустые строки, обычные task, нумерованные сценарии, TESTS/PASSED и понятный PASS/FAIL. Перед созданием можно прочитать тесты соседних проектов в C:/Users/cosmo/VivadoProjects; их не изменять.
6. Комментарии на русском. Пояснять нетривиальные алгоритмы, условия, сложные составные имена и контракты. Не пересказывать очевидный смысл каждого порта или каждой строки. Допустимо краткое описание назначения сигналов в шапке.
7. Сохранять кодировку существующего файла. Для новых Verilog-файлов с русскими комментариями использовать совместимую с редактором Vivado Windows-1251; Markdown сохранять в UTF-8. Не перекодировать проект массово.
8. Работать поэтапно: описать конкретные действия и критерий, затем выполнять только порученный этап. WNS пользователь отложил до последнего этапа.
9. После проверки сохранять компактный итоговый журнал и убирать созданные временные сборки/излишки. Пользовательские исходники и исторические материалы без поручения не удалять.
10. Не делать длительные однотипные прогоны и случайный стресс без отдельного поручения. На обычное действие достаточно 1–3 примеров; остальные сценарии — конкретные граничные случаи, ошибки и переходы состояний.
11. В объявлениях портов не писать `input wire` и `output wire`. В Verilog обычные `input` и `output` без явного типа при стандартных настройках являются сетями `wire`. Выходу, которому присваивают значение в `always` или `initial`, указывать `output reg`.
12. Не использовать директивы `default_nettype none` и `default_nettype wire`, в том числе в конце файла. Все внутренние сигналы объявлять явно.

Явное исключение пользователя от 02.11.2026: в `tb_matrix_round.v` оставить два DUT (F и LSX), не разделять TB. При текущей переработке не изменять `tb_fifo.v`, `tb_key_input_order.v` и `tb_fifo_original.v`.
