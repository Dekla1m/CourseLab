# Текущий контекст CourseLab

Актуально на **8 ноября 2026 года**. Рабочий проект — [CourseLab.xpr](../CourseLab.xpr). Правила Verilog, симуляции и оформления — в [AGENTS.md](../AGENTS.md).

## Состояние

- Вычислительное ядро ENC готово на уровне функциональной симуляции. `Encrypt_TOP` принимает блок, ключ и `last` по handshake и выдаёт результат через 35 тактов. Проверены расписание, все 32 Ci и занятость сообщения. [Encrypt_TOP](ENCRYPT_TOP.md)
- Блочный DEC реализован с портами Encrypt_TOP. Обратные раунды выполняются после развёртывания ключей. Симуляция: 10/10 сценариев, 43 такта. [Decrypt_TOP](DECRYPT_TOP.md)
- Реализованы универсальный FIFO и отдельный разбор ключа с удержанием готового результата. Активный ключ для целого сообщения предстоит хранить в отдельном аппаратном блоке. [FIFO и тесты](FIFO.md), [требования к ключу](KUZNYECHIK_TZ_AND_L.md#15-занятость-сообщением-и-аппаратная-смена-ключа)
- Ввод данных умеет собирать байтовые блоки ENC. Системный тракт с выходным форматированием, обработкой сообщений DEC и CPU пока на стадии проектирования и отдельных модулей. [Архитектура](ACCELERATOR_ARCHITECTURE.md)
- После RX FIFO арбитр выбирает загрузчик или рабочий тракт. CPU выбирает `KEY / DATA / PAUSE` через регистры и получает команды из памяти программ. Вход в загрузку и запрос ENC/DEC задаются кнопками. Рабочие настройки меняются регистрами в пределах ресурсов текущего битстрима. [Загрузчик и системная шина](SYSTEM_BUS_AND_PROGRAMMER.md)

## Рабочие файлы и проверка

Исходники находятся в `CourseLab.srcs/sources_1`, тесты в `CourseLab.srcs/sim_1`, ограничения в `CourseLab.srcs/constr_1`. RTL с русскими комментариями хранится в Windows-1251. Текущий `sim_1` связан с `sources_1`, а нужный TB выбирается как Simulation Top.

- [check_crypto_tests.ps1](../work/check_crypto_tests.ps1) запускает отдельные проверки `l`, `iterative`, `round`, `encrypt` и `decrypt`.
- [check_fifo_and_key.ps1](../work/check_fifo_and_key.ps1) запускает отдельные проверки `fifo` и `key`.
- [Журналы модульных симуляций](../outputs/unit_tests) содержат итоги PASS. Для `tb_matrix_round` действует исключение пользователя с двумя DUT. Остальные актуальные TB проверяют один DUT.
- Генераторы в `work` могут перезаписать рабочий RTL или TB. Для повторения проверки используются указанные сценарии запуска.

Работа идёт по этапам. Выполненные вехи и открытые решения перечислены в [NEXT_STEPS.md](NEXT_STEPS.md). Синтез, интеграционные симуляции и проверка платы запускаются по отдельному поручению. WNS остаётся последним аппаратным этапом.
